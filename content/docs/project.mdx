# Projects

Projects help you organize and track tasks by grouping them under meaningful categories. Whether you're managing work initiatives, personal goals, or creative endeavors, Task Genius provides flexible ways to define and visualize projects.

## Quick Start

<DeepLinkButton href="obsidian://task-genius/settings?tab=project">
  Open Project Settings
</DeepLinkButton>
<DeepLinkFallback />

## Understanding Projects

In Task Genius, a **Project** is a collection of related tasks organized under a common identifier.

### Two Ways to Define Projects

| Method | Description | Best For |
|--------|-------------|----------|
| **Task-Level** | Individual tasks tagged with project identifiers | Daily notes, scattered tasks |
| **File-Level** | Entire notes designated as projects | Dedicated project files |

**Task-Level Example:**
```markdown
- [ ] Design homepage #project/website
- [ ] Write API documentation #project/website
- [ ] Review code changes #project/backend
```

**File-Level Example:**

File: `Website Redesign.md`
```yaml
---
project: true
---

# Website Redesign

- [ ] Create wireframes
- [ ] Design color scheme
- [ ] Implement responsive layout
```

<Callout type="info">
A task can only belong to **one project** at a time. If both task-level and file-level projects are present, the task-level project takes precedence.
</Callout>

## Project Auto-Detection

<VersionCallout version="9.0.0" />

Task Genius can automatically detect and assign projects based on multiple sources. Enable this feature in settings to use advanced detection methods.

### Detection Priority

When multiple detection methods are enabled, Task Genius uses this priority order:

1. **Task-level metadata** (explicit tags like `#project/name`)
2. **File metadata** (frontmatter `project:` field)
3. **Config file** (`project.md` in folder)
4. **Path mapping** (folder path rules)
5. **Default naming** (fallback strategy)

---

## Source 1: Path-based Detection

Automatically assign projects based on file location in your vault.

### How It Works

Create rules that map folder paths to project names. Files in matched paths automatically belong to the specified project.

### Configuration

| Setting | Description |
|---------|-------------|
| **Path Pattern** | Folder path to match (e.g., `Projects/Work`) |
| **Project Name** | Project name to assign (e.g., `Work`) |
| **Enabled** | Toggle to activate/deactivate this rule |

### Examples

| Path Pattern | Project Name | Effect |
|--------------|--------------|--------|
| `Projects/Work` | `Work` | All files under `Projects/Work/` → "Work" project |
| `Areas/Health` | `Health & Wellness` | All files under `Areas/Health/` → "Health & Wellness" project |
| `Daily` | `Daily Notes` | All files under `Daily/` → "Daily Notes" project |

<Callout type="tip">
Path patterns support basic matching. For complex glob patterns like `**/*.md`, use the advanced detection methods.
</Callout>

---

## Source 2: Metadata-based Detection

Read project information directly from file frontmatter (YAML metadata).

### How It Works

Add a `project:` field (or your custom field name) to a file's frontmatter. All tasks in that file inherit this project.

### Configuration

| Setting | Description | Default |
|---------|-------------|---------|
| **Enable metadata detection** | Toggle metadata-based project detection | Off |
| **Metadata field name** | The frontmatter key to read project from | `project` |

### Usage Examples

**Simple (uses filename as project name):**
```yaml
---
project: true
---

# Q1 Marketing Campaign

- [ ] Plan social media strategy
- [ ] Design ad creatives
```
Result: Tasks belong to "Q1 Marketing Campaign" project

**Explicit (uses specified name):**
```yaml
---
project: "Marketing Initiatives"
---

# Q1 Marketing Campaign

- [ ] Plan social media strategy
- [ ] Design ad creatives
```
Result: Tasks belong to "Marketing Initiatives" project

---

## Source 3: Config File-based Detection

Use a special configuration file in each folder to define project settings for all files in that folder.

### How It Works

1. Create a configuration file (default: `project.md`) in a folder
2. Define project properties in its frontmatter
3. All files in that folder inherit these project settings

### Configuration

| Setting | Description | Default |
|---------|-------------|---------|
| **Enable config file detection** | Toggle config file-based detection | Off |
| **Config file name** | Name of the configuration file | `project.md` |

### Example

**Folder structure:**
```
Projects/
  Website/
    project.md        ← Configuration file
    design.md
    development.md
    testing.md
```

**project.md contents:**
```yaml
---
project: Website Redesign
priority: high
due: 2025-03-31
---

# Website Redesign Project

Project documentation and overview...
```

**Result:** All tasks in `design.md`, `development.md`, and `testing.md` automatically belong to "Website Redesign" project.

<Callout type="info">
The config file itself can contain tasks and documentation. It serves both as a configuration source and a potential project index.
</Callout>

## Advanced: Custom Detection Methods

Beyond the three main sources, configure additional detection methods for specialized workflows.

### Detection Method Types

| Type | Description | Example |
|------|-------------|---------|
| **Metadata** | Read from any frontmatter field | `category: work` → project "work" |
| **Tag** | Extract from specially formatted tags | `#project/Work` → project "Work" |
| **Link** | Extract from wiki-links | `[[Projects/Work]]` → project "Work" |

### Tag-based Detection

Use tags like `#project/ProjectName` to assign tasks to projects:

```markdown
- [ ] Update documentation #project/website
- [ ] Fix login bug #project/backend
- [ ] Review budget #project/q1-planning
```

**Tag format:** `#project/your-project-name`
- Customize the prefix (`project`) in settings
- Project name follows the `/` separator

### Link-based Detection

Use wiki-links to project files:

```markdown
- [ ] Update documentation [[Projects/Website]]
- [ ] Fix login bug [[Projects/Backend]]
```

**Configure link path filter** to only match links containing specific paths (e.g., `Projects/`).

## Advanced: Metadata Field Mapping

Map custom frontmatter fields to standard task properties. Useful for:
- Custom naming conventions
- Internationalization (i18n)
- Integration with existing vault structures

### Configuration

| Setting | Description |
|---------|-------------|
| **Source Key** | Your custom field name (e.g., `proj`, `项目`) |
| **Target Key** | Standard Task Genius field (e.g., `project`, `priority`) |
| **Enabled** | Toggle to activate this mapping |

### Available Target Fields

- `project`, `context`, `priority`, `tags`
- `startDate`, `scheduledDate`, `dueDate`
- `completedDate`, `createdDate`, `recurrence`

### Example

**Mapping configuration:**
| Source | → | Target |
|--------|---|--------|
| `proj` | → | `project` |
| `ddl` | → | `dueDate` |
| `项目` | → | `project` |

**In your notes:**
```yaml
---
proj: Website
ddl: 2025-03-31
---

- [ ] Complete homepage design
```

Task Genius interprets `proj` as `project` and `ddl` as `dueDate`.

## Fallback: Default Project Naming

When no project is detected by the above methods, use a fallback strategy.

### Naming Strategies

| Strategy | Description |
|----------|-------------|
| **Filename** | Use the current file's name as project name |
| **Folder name** | Use the parent folder's name as project name |
| **Metadata** | Use a specified metadata field value |

### Configuration

| Setting | Description | Default |
|---------|-------------|---------|
| **Enable fallback naming** | Generate default project name when none detected | Off |
| **Naming strategy** | How to generate the project name | `filename` |
| **Remove file extension** | Strip `.md` from filename (for filename strategy) | On |

### Example

With **filename** strategy and file `Website Redesign.md`:
- Tasks without explicit project → assigned to "Website Redesign" project

With **folder name** strategy and file `Projects/Work/meeting.md`:
- Tasks without explicit project → assigned to "Work" project

## Project View

The Project View provides a dedicated interface for managing project-based workflows.

### Opening Project View

1. Open the Task Genius View
2. Select **"Projects"** from the left sidebar
3. Browse projects on the left, view tasks on the right

### Display Options

| Setting | Description | Default |
|---------|-------------|---------|
| **Default project view mode** | `list` (flat) or `tree` (hierarchical) | `list` |
| **Auto-expand project tree** | Expand all tree nodes by default | Off |
| **Show empty project folders** | Display folders without tasks | Off |
| **Project path separator** | Character for hierarchy (e.g., `/` in `work/frontend`) | `/` |

### Tree View

Projects with hierarchical names (e.g., `work/frontend/website`) display as nested trees:

```
work/
├── frontend/
│   └── website    (3 tasks)
│   └── mobile     (2 tasks)
└── backend        (5 tasks)
```

**Benefits:**
- Visual hierarchy for nested projects
- Expand/collapse for focus
- Click parent to see all child project tasks

## Best Practices

### 1. Choose One Primary Method

While you can combine methods, pick one primary approach:

| User Type | Recommended Method |
|-----------|-------------------|
| Daily Note Users | Task-level tags (`#project/name`) |
| Structured Vaults | Folder-based detection |
| MOC Users | Frontmatter metadata |

### 2. Use Consistent Naming

Standardize project names to avoid fragmentation:

✅ **Good:**
```markdown
#project/website-redesign
#project/website-redesign
#project/website-redesign
```

❌ **Avoid:**
```markdown
#project/website-redesign
#project/WebsiteRedesign    ← Different name!
#project/website_redesign   ← Different name!
```

### 3. Archive Completed Projects

Keep your Project View clean:
- Move finished project files to an `Archive/` folder
- Remove or change the `project:` frontmatter
- Use a custom tag like `#project-archived`

### 4. Combine with View Modes

Use different view modes for project tasks:
- **List View:** Flat task list
- **Kanban View:** Status-based columns
- **Calendar View:** Timeline visualization
- **Tree View:** Hierarchical task structure

## Troubleshooting

### Project Not Detected

**Issue:** A file isn't showing up as a project.

**Solutions:**
1. Verify the detection method is enabled in settings
2. Check frontmatter syntax: `project: true` or `project: "name"`
3. Ensure file is in the specified folder path
4. Run `Task Genius: Force reindex all tasks`

### Tasks Not Appearing in Project

**Issue:** Tasks don't show up when viewing a project.

**Solutions:**
1. Check tag spelling: `#project/website` not `#projects/website`
2. Ensure no extra spaces: `#project/website` not `#project/ website`
3. Verify file-level project is properly configured
4. Refresh the view or restart Obsidian

### Task in Wrong Project

**Issue:** A task appears under the wrong project.

**Solution:** Check for conflicting assignments. Explicit task-level tags override file-level projects.

### Duplicate Projects

**Issue:** Same project appears multiple times with different names.

**Solution:** Search your vault for naming variations and standardize them. Use find-and-replace for bulk updates.
